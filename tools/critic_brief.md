# Задание критику 3D-моделей атласа «Кто мы? — от молекулы до мысли»

Проект: интерактивный 3D-атлас человека на three.js (по-русски), для студентов-медиков и любознательных взрослых.
Репозиторий: /home/user/Chelovek (ветка source). Код сцен:
- сцены «Тело», «Клетка», «Мозг» — функции `makeXxx` в `/home/user/Chelovek/src_page.html` (огромный файл, ищи `function makeXxx(` через Grep и читай кусками с offset/limit; соответствие id → функция в строке `const BUILDERS = {`);
- сцены «Биохимия» — файлы `/home/user/Chelovek/bio/NN_name.js` (строка `// @scene <id> <makeFn> | Название | Группа`), общий набор деталей — `bio/01_biokit.js`, молекулы — данные `data/mols.json`, белки — `data/pdb.json`.
- Некоторые сцены грузят готовые 3D-модели из Sketchfab (models/*.txt): skeleton, muscles, vision, digest, repro. Эти файлы НЕ меняются; критиковать можно только то, как сцена их показывает (камера, материалы, подсветка, подписи, добавленные процедурные детали).

Снимки: `/home/user/Chelovek/lt/rev/<id>_m1.jpg … _mN.jpg` (режимы 1..N), `<id>_side.jpg` (камера повёрнута мышью), `<id>_close.jpg` (приближение колесом к центру экрана). Панель управления и заголовок на снимках скрыты, подписи 3D оставлены. Рендер — программный (SwiftShader), так что лёгкая «зубчатость» не дефект.

## Что делать
Ты — строгий рецензент: анатом/биохимик + 3D-художник. Ничего не меняй в проекте, только смотри снимки (инструмент Read открывает jpg) и читай код.
Для каждой своей сцены:
1. Посмотри ВСЕ снимки сцены.
2. Найди дефекты именно 3D-модели и её показа:
   - научная/анатомическая ошибка формы, пропорций, взаиморасположения, цвета-кодировки, числа структур (например, не та сторона, лишняя/недостающая часть, неправильная форма молекулы);
   - визуальные: части пересекаются/торчат друг сквозь друга, висят в воздухе, z-fighting, слишком грубые примитивы (видна «гранёность», цилиндры вместо органических форм там, где это портит понимание), объект не в кадре/обрезан/слишком мелкий, всё тёмное или пересвечено, сливается с фоном, нечитаемая каша;
   - подписи: указывают не туда, налезают друг на друга, подпись есть, а объекта не видно.
3. Для каждого дефекта найди место в коде (файл и функция/строка) и предложи КОНКРЕТНОЕ исправление (что поменять: координаты, радиус, сегменты, материал, камеру; какую геометрию добавить). Исправление должно быть посильным правкой кода, а не «сделать новую модель в Blender».
4. Поставь сцене оценку 1–5 (5 — отлично, менять нечего).

## Формат отчёта
Запиши отчёт в файл `/home/user/Chelovek/lt/review/<твоя группа>.md` (создай папку при необходимости) и верни его же кратко в ответе. Структура:

```
## <id> — <название> — оценка N/5
1. [серьёзность: высокая|средняя|низкая] <что не так, на каком снимке> → <где в коде> → <как исправить>
2. ...
```
Сначала самые серьёзные. Не больше 6 пунктов на сцену; если сцена хороша — так и напиши одной строкой. Не придирайся к тому, что не исправить разумной правкой. В конце — список «топ-10 по группе» самых важных исправлений.
