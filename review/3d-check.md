## Проверено, в порядке

- **Б1, `GLASS`-материалы без `xray`:** uRim/uBase/uFlash меняются только в `applyLook`/`glassMat` (520, 529) и uFlash в 5620 (в `update`, до проверки видимости в `frame`). Других записей нет. При всех трёх нулях альфа = 0 и в Additive, и в Normal смешении — картинка не меняется. `material.visible` в сценах для стекла нигде не переключается руками (все `.visible=` в сценах — на мешах/группах), конфликта нет. `raycast` не смотрит `material.visible`, выбор по клику стекла не меняется. `keep:true`-стекло в `GLASS` не попадает — остаётся видимым.
- **Б2 `forceSinglePass`:** только при `additive`; в r160 двухпроходная отрисовка условна `transparent && DoubleSide && forceSinglePass===false` (render и prepareMaterial/compile). Аддитивное смешение коммутативно, `depthWrite:false`, порядок задней/передней грани не важен — результат тот же. Для Normal-стекла путь прежний.
- **Б3 `antialias:false`:** `EffectComposer` r160 создаёт цели без `samples` (HalfFloat, MSAA нет), MSAA холста работал только на полноэкранном квадрате `OutputPass` — картинка не меняется. Запись (`REC`) и `setPixelRatio` в режиме съёмки не зависят.
- **Б4:** `matchMedia` вызывается при построении сцены, скобки/порядок выражений корректны; тени получает только `ShadowMaterial` пола. **Б8** — только DPR.
- **Б5:** `Light.dispose()` (Directional/Point/Spot) = `shadow.dispose()`; сработает только там, где `shadow.map` есть (кроме скелета теней ни у кого нет); `InstancedMesh.dispose()` только снимает буферы инстансов, геометрию/материал не трогает, не вызывается для `cur`. Общие объекты (`GLOW`, `envTex`) по-прежнему исключены. Света создаются `addLights` на сцену — общих между сценами нет.
- **Б6:** `#heartpanel` ищется по id; `close` идемпотентна для `activate` (панель одна), `onEsc` снимается; `clock` — core-переменная, `split.mjs` импортирует её в чанк скелета автоматически (проверок «core использует вкладку» не нарушено: в `activate` только строка `'heartpanel'`). `dt` после закрытия ограничен 0.05 и сбрасывается `clock.getDelta()`.
- **Б7:** `statsEl.__k` сравнивается с JSON значений; `statsEl` больше нигде не пересоздаётся/не очищается (только `updateStats`), значения — примитивы; при смене сцены другой набор даёт другой ключ. Первый кадр (`__k` не задан) строит DOM.
- **С2, остальное:** `OrbitControls.update()` в r160 возвращает true при любом сдвиге камеры, включая `flyStep`/`camStep`/демпфирование (сравнение с lastPosition), поэтому перелёты и «довод» считаются. `ANIM.dt` нужен только `flyStep`. Сцены не используют `performance.now()`/`clock` вне `st.t` (которое на паузе стоит). События: клик/клавиши/input/pointermove/wheel/touchstart окружают все действия пульта; догрузка модели видна максимум через секунду. `camFly`, `REC`, `IDLE` объявлены до `frame`, TDZ нет.
- **С5, остальное:** цель композера выбрана верно (`RenderPass` рисует в `readBuffer` → те же `toneMapping=None`, `outputColorSpace=Linear`, как при рендере); `setRenderTarget` восстанавливается в `finally`; без `KHR_parallel_shader_compile` путь прежний (`go()` синхронно); `__ready` ставится в `activate`, все инструменты ждут 90–180 с — задержка до 3 с безопасна. Повторный `show(тот же id)` во время компиляции активирует сразу, старый `go` отсекается seq. Гонка «другая тема» отсекается по seq (кроме замечания про `recent`).
- **С3:** все 3 `add` используют только `k` и `mat` (числа, булевы, `THREE.Color` → `toJSON` даёт hex; текстур/функций в `mat` нет — проверено по всем вызовам). Нигде в сценах нет `mesh.material.*` для объектов из `add()`: изменения материала идут через `PART[id].mats` (`dimOthers`, `PART.cor.mats`), либо для отдельных `Mesh`, не созданных `add` (alvMat, bolus, ring, spr). В лёгких оба лёгких теперь делят материал: `select()` ставит им одинаковое opacity — эквивалентно. `PART.tr.mats[0]` (кольца трахеи) по-прежнему первый материал части. `mats` без дубликатов, `disposeScene` собирает материалы в Set.
- **С4:** число и порядок вызовов `rnd()` те же (одно на путь), так что раскладка и фазы совпадают с прежними; `PATHS` объявлена до первого `path()` (1359); `mergeGeometries` получает однородные TubeGeometry (position/normal/uv/index + aPhase); `apply()`/`update()` работают с `children` с `uniforms` (теперь один меш на систему, `uOn`/`uTime` — общий, как и раньше были общими значения); спрайты/ядра без `uniforms` обрабатываются веткой `else`. Исходные геометрии dispose'ятся до загрузки в GPU — безопасно.
- **Splitter:** новые идентификаторы (`IDLE`, `MC`, `PATHS`, `go`) локальные или core-only; `tools/split.mjs` не получит записей в core-переменные из чанков.
