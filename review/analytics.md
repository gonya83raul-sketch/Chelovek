# Аналитика для «Кто мы?»: варианты, cookie, service worker и план событий

Ничего не подключал и не менял. Смотрел исходники (`src_page.html`, `pwa/sw.tpl.js`) и сборку в `out/`. Папки `app37/` и `~/work/chelovek-site` локально нет, поэтому опирался на шаблоны. Юридические оценки ниже — рабочая ориентировка, не юридическая консультация.

## 1. Как устроен сайт (важно для аналитики)

- **Хостинг.** Статический сайт на GitHub Pages: один домен, сервера нет. У каждой темы своя страница: `krebs.html`, `krebs.en.html`.
- **Переходы между темами не перезагружают страницу.** Адрес меняется через `history.pushState` в `activate()` (`src_page.html:10039-10045`). Счётчик сам увидит только первую загрузку, остальные просмотры нужно отправлять вручную из `activate()`.
- **Service worker (`pwa/sw.tpl.js:33-53`) перехватывает только свой домен, Google Fonts и jsdelivr.** Запросы к счётчикам на других доменах (`mc.yandex.ru`, `*.goatcounter.com`) идут мимо него:
  - сам sw.js ломать или переписывать не нужно;
  - без сети такие запросы просто молча не проходят, поэтому без своей очереди всё, что происходит офлайн, в статистику не попадёт;
  - адреса счётчика нельзя добавлять в `SHELL` и в `offline.json`, иначе «Сохранить для офлайна» сломается на чужом домене.
- **Медленная сеть.** Страница открывается сначала из сети, а через 4 с — из кэша (`sw.tpl.js:43-45`). JS выполняется и у сохранённой копии, так что такие визиты считаются, если сеть всё же есть.
- **Уже есть хорошая метрика вовлечённости.** Тема помечается «изучено», если человек провёл на ней 10 с активно (`markSeen`, `src_page.html:10157-10162`) или прокрутил к тексту. Это лучше, чем голое «открыл тему».
- **Шумовые визиты, которые надо отсекать:**
  - режим записи `?rec` (флаг `REC`);
  - скриншоты и проверки через Playwright (`tools/siteshots.py`, `pwatest.py`) — их видно по `navigator.webdriver === true`;
  - `localhost`;
  - офлайн-файл без `meta[name="atlas-pages"]`.
- **Google Fonts уже передаёт IP посетителей в Google.** К выбору счётчика это не относится, но для политики конфиденциальности стоит учесть.

## 2. Варианты

### A. Яндекс Метрика (`tag.js`)

**Что видно:**
- визиты, отказы, глубина;
- источники с хорошей детализацией для РФ: Яндекс-поиск, Дзен, VK, Telegram;
- города, устройства, браузеры;
- цели и параметры визита, воронки (на Метрике можно строить «открыл тему → запустил процесс → изучил»);
- карта кликов.

Вебвизор я бы не включал: запись холста с 3D бесполезна, а для приватности тяжело.

**Нужен ли баннер про cookie: да.** Метрика ставит cookie (`_ym_uid`, `_ym_d`, `_ym_isad`) и получает IP и данные о браузере. По практике Роскомнадзора это персональные данные по 152-ФЗ. С 1.09.2025 согласие на их обработку оформляется отдельным документом. Нужны:
- политика конфиденциальности;
- баннер или окно согласия, причём Метрику загружать только после «Согласен»;
- для английской аудитории из ЕС по GDPR — то же самое, только строже.

Плюс для РФ: данные хранятся в России, вопроса о передаче за границу нет.

**Как работает с sw.js:**
- `tag.js` грузится с `mc.yandex.ru`, sw.js его не кэширует;
- без сети скрипт не загрузится, вызовы `ym()` останутся в очереди в памяти и пропадут при закрытии вкладки;
- на кэш и офлайн это никак не влияет.

**Особенности:**
- для перехода между темами — `ym(ID,'init',{defer:true,…})` плюс ручной `ym(ID,'hit',url)` в `activate()`, чтобы не было двойных просмотров;
- цели — через `reachGoal`;
- скрипт весит примерно 60–90 КБ;
- около 20–30 % пользователей блокировщиков рекламы в статистику не попадут.

### B. GoatCounter — счётчик без cookie

Бесплатный облачный тариф для некоммерческих сайтов или собственный сервер. Близкие аналоги: Umami Cloud, Plausible (платный).

**Что видно:**
- просмотры страниц;
- рефереры;
- страны;
- браузеры, ОС, размер экрана;
- события — как отдельные «пути» с флагом `event:true`.

Чего нет:
- воронок;
- параметров событий (тему приходится зашивать в имя: `process_started/krebs`);
- сегментов.

Для решения «какие темы смотрят и что нажимают» этого хватает.

**Нужен ли баннер про cookie: нет.**
- Cookie и localStorage счётчик не использует.
- IP не хранит: уникальность считается по хешу с суточной солью.
- В ЕС обычно обходятся без баннера.
- В РФ формально IP всё равно уходит на зарубежный сервер. Риск низкий, но строчку в политике конфиденциальности стоит добавить, а доступность сервиса из РФ — проверить.

**Как работает с sw.js:**
- скрипт `count.js` (~3,5 КБ) можно положить на свой домен в папку версии; тогда sw.js закэширует его как неизменяемый файл, и он будет загружаться офлайн;
- сам запрос-счётчик идёт на домен GoatCounter, мимо sw.js, и без сети пропадает;
- к GoatCounter легко добавить свою очередь, она описана в разделе 3.

### C. Комбинация: GoatCounter для всех + Метрика только после согласия

- GoatCounter считает всех без баннера: темы, события, общий объём.
- Метрика подключается, только если человек нажал «Согласен». Она даёт российские источники трафика и воронки по согласившимся.
- Нужно поддерживать два счётчика и всё равно делать баннер и политику.

### Рекомендация

Начать с **B (GoatCounter)**: без баннера, лёгкий, проблем с sw.js нет, данных для решений по темам достаточно. Переходить к **C** имеет смысл, если важно понимать, откуда приходят люди из Яндекса, Дзена и VK, и вы готовы к баннеру и политике. **A** отдельно — только если нужна именно Метрика целиком.

## 3. Офлайн-режим: что делать с событиями без сети

Ни один из вариантов сам не накапливает события офлайн. Если это нужно, вот небольшая обёртка:

- `track(name, props)` при `navigator.onLine === false` или ошибке запроса кладёт событие в localStorage (лимит примерно 200 штук);
- при событии `online` или следующем запуске очередь досылается через `navigator.sendBeacon` или `fetch`;
- исходное время события счётчики не принимают, поэтому событие учтётся на момент отправки — для этого сайта это нормально;
- отдельно отмечать «запуск без сети» (`session_offline`), чтобы понять, пользуются ли вообще сохранённой копией.

## 4. План событий

Единое правило: имена `объект_действие` в нижнем регистре; язык — параметром `lang`, а не отдельными событиями. Номер карты из окна «Поддержать», адреса и любые личные данные не отправлять.

| Событие | Где в коде | Параметры | Что даёт для решений |
|---|---|---|---|
| `page_view` (просмотр при переходе) | `activate()`, `src_page.html:10022`; для режима без WebGL — `show()`, ~10010 | `topic`, `sec`, `lang` | какие темы открывают; заменяет «открытие темы» |
| `topic_opened` | там же, только при переходе внутри страницы (не первая загрузка) | `topic`, `from`: `nav` / `search` / `back`; `fromPop` → `back` | как ходят по атласу: меню, поиск или «Назад» |
| `topic_studied` | `markSeen()`, 10158 / 10162 | `topic`, `lang` | **главная цель**: тему действительно изучили (≥10 с активно или дочитали) |
| `process_started` | общий помощник `button(text, onclick, primary)`, `src_page.html:618`: обернуть `onclick` у `primary=true` («Запустить», «Импульс», «Проглотить кусочек»…) | `topic`, `n` (номер кнопки, а не переведённый текст) | работают ли интерактивные опыты; **ограничение — один раз на тему за сессию**, иначе «Авто» и повторные нажатия дадут шум |
| `offline_save_started` | обработчик нажатия, 10471 | `lang`, `mb` (объём округлённо) | интерес к офлайн-режиму |
| `offline_save_completed` / `offline_save_failed` | 10492-10494; отказ из-за места — 10475 | `bad` (число файлов), `reason`: `quota` / `net` | доходит ли загрузка до конца (≈ сотни МБ), где ломается |
| `language_switched` | 9879 | `from`, `to`, `topic` | спрос на EN-версию; **отправлять через `sendBeacon`** — сразу после клика уходит `location.href` |
| `donate_opened` | 9885 | `topic` | сколько людей интересуется поддержкой |
| `donate_option_clicked` | ссылка Boosty (357), «Скопировать адрес» `#dcopy` (9889) | `option`: `boosty` / `crypto` | какой способ поддержки выбирают (только способ, без адреса и сумм) |

Дополнительно — дёшево и полезно для 3D-сайта:
- `app_installed` (10446);
- `update_applied` (кнопка «Обновить», 10454);
- `webgl_unavailable` (ветка без WebGL в `show()`) — сколько людей не видят 3D вообще;
- `session_offline`.

**Цели в Метрике (если выберете A или C):** `topic_studied`, `process_started`, `offline_save_completed`, `donate_option_clicked`.

**Где подключать:** только в сборке сайта (`tools/build.py`, страницы с `atlas-pages`), но не в офлайн-файле. Все вызовы — через одну функцию `track()`, которая молчит при `REC`, `navigator.webdriver`, `localhost` и отсутствии согласия (для Метрики).

**Проверка после подключения:**
- события по одному разу на каждое действие, без дублей просмотров при переходах;
- `language_switched` доходит до счётчика;
- офлайн нет ошибок в консоли, «Сохранить для офлайна» работает как раньше, в `chv-*` не появились чужие адреса;
- скриншоты из `tools/siteshots.py` не попадают в статистику.
