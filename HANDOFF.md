## 3. Первый запуск на новой машине
```sh
git clone https://github.com/gonya83raul-sketch/Chelovek.git chelovek-src
cd chelovek-src && git checkout source
sh tools/setup.sh                     # модели из ветки main, three.js для тестов, pillow+playwright
python3 -m playwright install chromium   # если браузер для playwright ещё не стоит
python3 tools/build.py                # сборка → out/ и lt/
cd lt && python3 -m http.server 8765  # локальный сервер (оставить работать в отдельном окне)
```
Нужны: git, Python 3.10+ (pip: playwright, pillow, numpy), Node 18+ (npm). На Windows удобнее всего WSL или Git Bash.
Проверка: открыть http://127.0.0.1:8765/index.html#referred — должна открыться сцена «Отражённая боль».

## 5. Как устроена сцена (шаблон)
Функция `makeX()` возвращает объект:
`{ mobZoom?, scene, camera, controls, update(dt), ui(el), onKey(e), stats(), labels, drawScope(ctx,w,h) | null, accent, kicker, title, lede, notes }`.
- Режимы: `st.mode`, `setMode(m)`, перелёт камеры `st.fly = flyTarget(target, pos)` + `flyStep(st, camera, controls, dt)` в update.
- Мобильная камера: `const VIEWM = {...}, mqm = window.matchMedia('(max-width:700px)'), VV = (m) => (mqm.matches && VIEWM[m]) || VIEW[m];`
- Подписи: `{ text, pos: V3, color, show: () => bool }`; подвижная подпись — `pos` как функция, затем в update копировать (образец в bio/85_pituitary.js).
- UI-помощники: `seg`, `toggle`, `button`, `group`, `infoBox`, `h`; клик по объектам — `pickOn(() => self, camera, meshes, cb)` (у меша `userData.pick`).
- 3D-помощники: `organMat`, `glassMat(col,{keep:true})`, `ell3`, `blobGeo`, `tube`, `taperTube`, `glowNucleus`, `flowArrow`, `Sparks`, `bodyShell` (условное тело), `skelShell` + `loadSkeletonStatic` (настоящий скелет, body/10_planes.js), `SKEL_META` (суставы), `makeVessels` (сосуды скелета).
- Система координат скелета: 1 ед. ≈ 10 см, рост ≈ 17,1; **x > 0 — ЛЕВАЯ сторона человека**, z > 0 — вперёд; череп y 14.88–17.14.
- Кадр на десктопе 1440×900: снизу панель, слева сверху заголовок, справа сверху статистика. Видимая часть — верхние ~65% холста. Удобно: смещать цель камеры, чтобы объект был справа-сверху (см. `VW()` в body/12_referred.js).

## 10. Алгоритм работы с экономией токенов (обязательно)
Работать по этим шагам. Цель — меньше чтения, меньше снимков, меньше повторных проверок, при том же качестве.

**Модели:** Haiku — рутина (grep, сборка, sweep, перевод, публикация). Sonnet — сцены, правки, рецензии. Opus — сложная геометрия (скелет, сосуды, нервы) и спорная анатомия.

**Этап 1. Подготовка темы (дёшево)**
1. Искать место через `grep`, а не читать `src_page.html` целиком: `grep -n "makeX\|@scene" src_page.html bio/*.js body/*.js`.
2. Рендерить только нужную страницу Неттера: `pdftoppm -f N -l N -r 80 -png <pdf> <out>`.
3. Записать план в `review/plan-<тема>.md`: 5–10 пунктов, что добавить, что исправить, какие подписи.

**Этап 2. Сборка сцены**
4. Писать сцену в `body/` или `bio/`, используя помощники из раздела 5. Существующие функции без необходимости не переписывать.
5. Добавить id в `tools/ids.txt`.
6. Быстрая проверка одной сцены: `python3 tools/sweep.py <id>`. Полный прогон — только перед публикацией.
7. Снимки минимально: десктоп 1440×900, телефон 390×844 и один кадр EN. Остальные режимы — только если менялась их логика.

**Этап 3. Рецензент (дорогой этап)**
8. Один рецензент на тему. Второй — только для крупных тем (например, «Череп»).
9. Агент со свежим контекстом, не fork. Задание короткое, по шаблону раздела 7.
10. Модель рецензента: `model: "sonnet"`. Opus — только для сложных анатомических тем.
11. Отчёт короткий: таблица `№ | серьёзность | где | проблема | исправление`, не больше 30 строк, в файле `review/<имя>.md`. Агенту в ответе — только счётчик по уровням и путь.
12. Исправлять высокие и средние. Низкие — в список «на потом» в `NOTES.md`.
13. Повторную рецензию на мелкие правки не запускать.

**Этап 4. Перевод**
